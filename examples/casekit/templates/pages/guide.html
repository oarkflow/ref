How this works

The idea in four lines

  1. A workflow is a list of stages. Starting one creates a case with a number.
  2. A stage is handled by one kind of person: the applicant (public) or staff with a role.
  3. Checks on a stage must pass before its Approve or Continue button works.
  4. My work lists cases waiting for the role you are signed in as.

Users and roles

There is no username and password here. A user is a signed token holding an id and roles. Without one you are an applicant: you can start cases and fill public stages. On a demo server the header has one-click sign-in buttons.
