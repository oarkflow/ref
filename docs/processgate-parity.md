# ProcessGate feature parity audit

Source: the user-provided **ProcessGate — Features by Level (2026-10-27)** catalog. This is an implementation audit of REF and the configuration-only medical coding example, not a claim that REF is already a ProcessGate replacement. A BCL field or action name counts as implemented only when its runtime behavior and an end-to-end test are present.

The [pipeline migration example](../examples/processgate-pipelines/) adds 102 structural flow definitions from the ProcessGate scripts and bundles. Its `manifest.json` lists source paths and per-flow behavior requiring manual work; the migration does not change the partial parity ratings below.
The example now runs authenticator-app registration, per-flow anonymous entry, dated schedule submissions, field review and multi-person approval nodes, an RFI pause and response, stage rollback actions, a payment completion gate with a configurable verification intent, and durable in-app notifications. Source bundles still leave verification scopes, some assignment and rollback rules, payment gateways and amounts, and several domain event mappings ambiguous. Those remain in the manifest rather than being labeled complete.

**Status key:** *Foundation* means a reusable runtime primitive exists. *Partial* means some catalog behavior exists but the full user-facing feature does not. *Unverified* means this audit found no sufficient implementation evidence. All 21 feature levels require further work for complete parity.

## Verification gate for every remaining feature

1. Define the BCL or API contract and tenant/role boundaries.
2. Implement persistence and runtime behavior, including failure and retry cases.
3. Provide the builder or end-user interface where the catalog names one.
4. Add an end-to-end test that exercises the actual route or UI with at least two roles or tenants when access is involved.
5. Document deployment requirements and mark the row complete only after the test passes.

The catalog's own caveats remain open questions: asynchronous validation, shorthand cross-field references, payment, external SSO/OAuth, SLA automatic actions and artifact generation need direct runtime tests before they can be called complete. REF's existing primitives do not prove these ProcessGate product flows.
